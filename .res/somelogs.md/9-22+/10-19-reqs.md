## 5. Automatic rotation for long sessions

**The problem.** Reconnecting to a harness session means `session/load`, and the harness replays the whole history to us. With a 17,000-line transcript that takes about a minute. It gets worse as the session grows, and the user waits every time it's reopened. The harness's own compaction doesn't help here: it shrinks the model's context, not what gets replayed on load.

**The idea.** Before a session gets that big, the library starts a new harness session and carries the conversation over with a handoff summary. The conversation continues and the user sees one conversation.

**Most of it already exists.** Crash recovery does exactly this: checkpoint recovery (`recoverInPlace`) opens a new provider session from a published checkpoint, and `provider_reconnected via: "recovered"` reports it. Rotation would be the same move done on purpose, between turns, instead of after a failure.

**What needs deciding:**
1. **When to rotate.** Options:
   - by size (records or replayed updates);
   - by measured load time (the last `session/load` took more than N seconds);
   - by context use from `usage_update`.

   I'd go with measured load time, since that's the actual pain, with size as a cheap stand-in before the first measurement.
2. **When it happens.** Only between turns, never during one. It could happen after a turn completes, or lazily at the next reopen, which saves the load entirely. I'd do it at reopen: when we see the session is too big, we skip `session/load` and start a new session from the checkpoint.
3. **Who writes the handoff.**
   - The checkpoint mechanism: it already exists, but checkpoint quality depends on whoever publishes it.
   - The library's internal inference: it could write the summary itself, which costs a model call.
4. **Opt-in, and visible.** It should be off by default, with a config such as `rotation: { maxLoadMs }`. Every rotation should be a visible event and a stored record, so nothing changes silently.
5. **What's lost.** Harness-side state the summary doesn't capture: exact earlier tool outputs, the harness's own memory. That's acceptable only if the consumer chose it.
