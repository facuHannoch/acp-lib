## The three read paths

**Live.** Frames arrive, `foldFrame(map, frame)` — a record replaces, a delta appends. One tool chip that fills in: title at 8, command at 13, output at 14.

**Reconnect mid-turn.** Subscribe → `session.activitySnapshot()` → `{active: true, seq: 11, records: [think-1, t1]}` → `foldRecords` those → then stream, discarding `seq <= 11`. The thinking block arrives whole, so the orphan-`append` problem doesn't exist. Reconnect *between* turns gets `{active: false, records: []}` — nothing to place, because the transcript already owns it.

**Cold reload.** `readTranscriptLines(path, {before, limit})` → `foldRecords` → last-wins on `recordId`. Turn 5's `t5:think-1` and turn 5's `t1` (well, `0:tool_...`) both survive alongside turn 4's, because minted ids are prefixed and protocol ids are session-unique. Grouping is by the `msg(user) → activity… → msg(assistant)` fences; a turn missing its trailing assistant message died in flight, and its `t1:announced` line tells you what it was doing.

Same fold function in all three. That's the property the whole design is for.

## What landed

**`src/agent-session.ts`** — one `ActivityAggregator` for the session's life, built in the constructor:
- `beginTurn()` calls `startTurn(mintTurnId())` at the top of `runPrompt`. The turn id is `Date.now().toString(36)` + 4 random chars — deliberately not a counter, so a resumed session can't collide with minted ids already on disk.
- `onActivity` now folds: `emitted` → transcript, `result` → `onRecord`, raw event → `onActivity` unchanged.
- `endTurn()` on **both** exit paths, before the assistant `msg`.
- `activitySnapshot()` for the mid-turn join.
- `transcriptActivity` accepts the config object (`kinds` / `checkpointOnInput` / `rawOutput` / `maxBytes`); `true` still works.

**`src/transcript.ts`** — the file contract as a module header, `recordId`/`reason`/`truncated` as named fields, and the backwards tail read: `{limit}` reads 64 KB chunks from EOF, carrying the leading partial line forward as **raw bytes** so a multi-byte character is never decoded mid-sequence.

## Five departures from the plan, four found by writing it

1. **`rawInput: {}` no longer counts as knowing the input.** The fixture (and Kimi) announce with that placeholder, so the `input` checkpoint never fired — R4 lost the command for any turn dying after it was known. New `hasInput()` treats `{}`/`[]`/`""`/`null` as "not yet". This is a fold-semantics change; `src/activity.ts:129`.
2. **`flush()`'s records also go to `onRecord`.** §3.5 only wrote them to disk — a live subscriber watching a cancelled turn would never learn the call ended and would spin a chip forever.
3. **`plan_update`/`plan_removed` added to default `kinds`.** An agent using the per-plan extension instead of full snapshots would have had its plans silently dropped.
4. **Shipped `toActivityRecord(line)` + `readActivityRecords(path, opts)`.** Un-flattening a line needed a cast and two `!` assertions that every reader would have written — exactly the "subtly wrong copies in the wild" R5 exists to prevent. `toActivityRecord` returns `null` for a 0.2.x raw line, which makes §8.1's self-discriminating argument executable.
5. **`client.ts` untouched.** §5 predicted ~5 lines of `onRecord` passthrough; unnecessary, since `AgentSession` fires it from its own wrapper. It's explicitly stripped from the handlers passed downward so there's exactly one place that can fire it.

Version stays **0.3.0** — I rechecked the registry, it's still unpublished (latest `0.2.0`), so the settled format and the `ActivityEvent` break ship together.
