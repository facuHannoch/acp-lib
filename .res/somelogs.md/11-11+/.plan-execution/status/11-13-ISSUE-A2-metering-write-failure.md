# A2: metering write failure and once-only record guarantee

Implementer report `controller-interface:library/reports/11-12-REPORT-A2.md` at `120210f`, open question 4: the spec says a turn's metering appears once, but a failure closing the metered operation or persisting its record can leave no metering record. The implementation can fail the turn; on a managed failure path a terminal transcript-write failure can be logged. The report also notes a failed Agent-owned metering-record write may be attempted again on the failure path using the same record. These are reported observations, independently reviewed as part of the current A2 follow-up, not established guarantees.

Question for spec owner via user: specify contract when metering finalization or its durable write itself fails. Must the turn fail, what result/event is guaranteed, and is absence of the durable record an explicitly named failure exception to the once-only guarantee? Distinguish one logical metering record from idempotent/retried write attempts and any mode-specific records. The user-approved ACP no-behavior-change scope should guide the decision; do not invent guaranteed durable persistence when persistence fails. The test watcher currently permits an absent record only for an explicitly declared write failure, and no characterization case declares one. Independent reviewer should assess whether the open question actually blocks the current gate or only future failure-path coverage.

Independent review `a54cad2` adds a distinct pre-dispatch boundary case: on a real managed session, `metering.open()` succeeded, then `v2Transcript.beginOperation()` threw a generic error before provider dispatch; no provider call occurred, and the watcher incorrectly classified it as failure before metering opened. Determine what metering result/record is required after open but before dispatch, and whether existing behavior is accepted for A2; this question is separate from metering persistence itself failing. The implementer was assigned to observe the boundary and characterize actual behavior without inventing a guarantee. The declared metering-write override is unused by current cases, as independently checked; no permission to omit required metering is inferred.
