## The code as it is

| Area | Current behavior and consequence for R5 |
| --- | --- |
| Harness ledger | The provider runner starts a logical call inside a running turn. The storage engine allocates a durable, session-scoped `callId`. A call has `channel`, `turnId`, a reserved assistant `messageId`, outcome, timestamps and ordered attempts. Each attempt has its own `attemptId`, ordinal, outcome, optional provider request ID and optional usage. Decision 0019 records absolute usage per attempt, fences late reports after timeout or cancellation, and keeps already committed usage across a crash. A timed-out or interrupted attempt can still carry billable usage. |
| Wire coverage | `ModelUsage` currently has optional `inputTokens`, `outputTokens` and `totalTokens`. The OpenRouter normalization emits those three fields. There are no cache categories, reported cost/currency, purpose or per-attempt provider/model identity in the summary. Both `channel` and `turnId` are required. The present store starts calls through a running turn, so it cannot produce a channel call between turns. Optional usages and fields mean unknown. An attempt that was started without confirmed usage has no zero-spend proof. |
| Pull and pagination | `session/model-calls({ after?, limit? })` reads the session-wide ledger. `after` is a call ID, `next` is the last call on a nonfinal page, and pages can end at either the count cap (100) or the frame byte cap. Unknown cursors fail with `not_found`. A single oversized summary fails with `transfer_limit`. Calls on different channels interleave. Later reads can change a running call already seen on an earlier page, including appending attempts. There is no turn selector, sealed per-turn manifest or snapshot fence in this RPC. |
| Native bridge | `NativeHarnessHost.modelCalls()` exposes the raw pages. `host.usage(channel?)` runs a separate aggregate scan, with missing-field counts. It loses call and attempt identity and isn't wired to the operation meter. `NativeController.subscribeUsageUpdate()` is a no-op. The controller resolves completed and cancelled turns with `usage: null`; terminal errors reject. Reconciled terminal outcomes and backend-started turns enter the same controller/turn path. The controller's local ID is `native-turn-<harness turn id>`. Reconciliation can also synthesize a failure when the harness has no turn record, which is different evidence from a committed terminal turn. |
| Operation boundary | `run-turn.ts` closes metering before the owned finalization and persists a metering record on provider failure too. `PersistedConversationLifecycle.meteringRecorded()` commits the record and state together and optionally appends a timeline reference. SQLite keys the commit by conversation and operation ID, compares stored content on repeat, and advances state once. Capture can discard old detail. This is the existing accounting path to reuse for native and the boundary at which to acknowledge pulled usage. |
| ACP and certification | Ordinary ACP uses the response/notification counters and the engine's cumulative or per-turn interpretation. OpenCode's plugin supplies normalized inference records through synchronous `InferenceSource` drains, with health and gap evidence. It is the only entry in `certification.ts` today. Engine construction checks the configured adapter ID against the registry and checks the source ID. For the plugin, `drainForeign` means other provider threads, and the engine both preserves that usage as unallocated and treats it as a billing attribution gap. Operation records expose totals and provenance, with no call or attempt IDs. The existing engine also associates an unallocated reported cost with OpenCode's USD convention. |

## Decisions to review before implementation

- **Source and key.** Put the native source in `src/metering/native/`. Give each Agent's native host one reusable ledger reader and each conversation a keyed view. Bound the request count and elapsed time of each pull. Keep publication per channel and let the same reader serve independent channel pulls without a host-wide queue. The metering key is the neutral `<Agent id>/<channel id>`. Today `NativeController.currentSessionId` and its start result return `host.sessionId`, shared across channels. Supply the channel-qualified key at the metering boundary and keep provider attachment/load identity intact. The conversation manager already knows the resolved adapter kind, host and channel when it creates a conversation. Use that binding to select the native source. The provider adapter ID can remain the caller's label in records. OpenCode keeps its present source and selection behavior.
- **Turn ownership and async pull.** A close for a dispatched native turn awaits the bounded pull before the synchronous `drain(key)`. Use the exact wire turn ID and channel, with the same close seam for held backend turns and recovered terminal outcomes. A pull publishes only the records for the turn being closed. Another channel's calls, another turn on the same channel, and unsealed attempts remain outside that drain. Use the wire association for ownership. The engine's sequence high-water logic is designed for OpenCode; a global native call ordinal would classify some held turns as late. Preserve call and attempt IDs in optional native metering evidence on the existing operation record. Keep one logical-call count and a separate attempt count. Account for each attempt with confirmed usage once, including retries that never returned a response. Retain attempt outcomes and field absences in the evidence. Use `sequence: null`. Native `providerID` and `modelID` remain unknown. The existing string-only inference view may use an empty sentinel, while persisted native evidence explicitly says unknown and is rated `pricing_unavailable` with a missing-route reason. The conversation's currently configured provider/model is not evidence of the route an earlier attempt used. Native observations from the current wire do not claim certified provenance.
- **Pages and recovery.** For the parity gate, read all pages after a committed terminal outcome. Use an atomic view at publication, detect repeated/nonadvancing cursors, and fail the read on a malformed, missing or oversized page. Use a per-channel high-water call ID derived from durable metering evidence. Advance only past that channel's sealed, accounted prefix, with an independent cursor for every other channel. Keep the cursor before an unresolved call so that a later pull rereads it as well as the new tail. A fresh or legacy meter with no saved cursor may need one bounded prefix scan. A paged read's last-seen ID alone is never the persisted high-water. On replay, use stable native turn operation IDs and the persisted record/state to prevent duplicate accrual, including when detailed records have been pruned. Check existing commit evidence before changing the in-memory meter on replay. A failed persistence commit must leave the evidence retriable. Reconcile a stored unavailable operation through the existing metering state/record path with the same operation ID. SQLite rejects a blind write of different content for an existing operation, so any repair must be explicit, atomic and idempotent. Avoid a second accounting ledger.
- **Between turns.** A call with an explicit channel and no turn belongs in that channel's `drainForeign(key)` and metering state's unallocated usage, whether it appears before, during or after an unrelated turn closes. Use an idle sweep with its own stable commit boundary so a last background call can be recorded without another prompt. Extend the native accounting path to distinguish this known allocation from an unexpected OpenCode thread. Expected native background usage should preserve turn completeness and remain visible and priced where evidence supports it. A record whose turn ID is unknown is a gap, not a background record. Calls with neither a turn nor a channel stay out of scope; the spec reserves `agent_metering_records` for that work.
- **Missing evidence.** Missing fields, nonterminal attempts, unaccounted records, fetch failure and inability to prove an empty turn must stay visible as unavailable or partial evidence. Preserve independently known attempts with their IDs, but never give an incomplete aggregate complete provenance. A provably undispatched operation or explicitly certified no-spend attempt can have exact zero with that proof. A missing turn or absent report cannot. An observed terminal turn with a running call or attempt is partial and must remain eligible for a later read. A host that is down at close also yields unavailable or partial evidence with the stable operation ID, for resolution on reopen. Once paid work has run, preserve its output and persist the metering failure. Strict native billing blocks further admission on that channel until the existing reconciliation path resolves the gap. Audit harness ingress paths too, including autonomous or backend-started work that can bypass the conversation prompt queue. For prices, use reported money with explicit currency when present and the catalog for the other attempts where identity and token categories support it. Keep reported and catalog prices distinguishable. An engine gap counter alone is insufficient today, since an outstanding gap only marks partial provenance in the generic engine.
- **Certification and open.** Add a library-owned `native-harness@1` entry selected by native adapter kind. Check the bundled executable's pinned protocol/feature description during conversation open without creating a harness session. The existing `describe()` is a server implementation function, and `initialize` advertises protocol 1 and the method name. Neither is evidence of the missing accounting semantics. Add the runtime confirmation at the shared host's `initialize` boundary, before `session/create` or `session/open`, including reopen. Those calls can admit resumed or backend work before a conversation submits a prompt. Register the strict requirement before any host admission that can reach a strict channel. If the host is already running, require a previously confirmed compatible handshake before opening a strict channel. Refuse custom commands and launchers in R5 because the library cannot establish static compatibility for them. The refusal names the native adapter kind and the missing accounting capability or unverified launch. A caller-provided source ID or the harness package's current `0.0.0` version alone carries no certification.

## Harness dependency

The existing wire is enough for the in-turn parity gate over reported input, output, total and IDs on sealed calls. It is insufficient for the full Usage design or for claiming that a partial or omitted attempt ledger is complete. Ask haurness-l for an additive accounting capability in the initialization description, with these guarantees and fields:

1. Explicit token category semantics (including cache inclusion/exclusion and the distinction between missing and zero), provider-reported amount and currency when supplied, stable provider/model identity for pricing, and extensible purpose. A fixed route can be described once if the harness can guarantee it for every attempt.
2. A sealed turn accounting boundary that covers all committed logical calls and attempts, including failed/aborted ones. Recommend an independently verifiable per-turn manifest of IDs, or counts and a durable fence with a scoped read that proves equivalent coverage. Document finality and the distinction between recorded zero attempts and unavailable data, including on recovery. An unconditional terminal event plus successful page traversal can prove parity with today's visible rows but cannot reveal an omitted row.
3. Explicit channel ownership with a nullable turn and a stable ID for between-turn work, when the harness can produce it. Coordinate a bounded background pull/idle trigger and admission behavior for a strict channel whose accounting becomes unavailable. The current harness has no producer for between-turn calls. A synthetic fixture can exercise the acp-client projection while this wire work is pending.

Keep these as harness-owned changes. R5 Done requires the observed-usage gates and explicit refusal of native `billing_required` on the current wire. Enabling certification and the pricing gate wait for the harness release. Registering the candidate kind in the library must convey its missing requirements without declaring the wire certified. R5 ships persisted evidence. Per-call usage events and native `TurnResult.usage` are deferred, and the spec status note records that boundary.
