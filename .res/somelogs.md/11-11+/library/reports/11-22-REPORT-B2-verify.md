## Step 5 — Backend-started turn path

[AgentSession](../../../../../src/agent-session.ts) L745–773 subscribes to the active controller's turn reports. A report with `sentBySession: false` goes to [backend-turns.ts](../../../../../src/conversation-turns/backend-turns.ts) L172–185, which retains the reporting controller, turn ID, cause and message IDs in a `backend_turn` queue item and wakes the queue. A stopped conversation abandons the report immediately. The pump dispatches the queued item at AgentSession L2386–2387. When it runs, `runBackendTurn` emits the public start with its cause, then calls the normal `runTurn` path with no `messages`. If a queued handoff has replaced the reporting controller, it abandons the item on the original controller. Stop abandons held turns and drops pending message handles; interrupt with queue clearing preserves already reported backend turns while dropping eligible messages.

[run-turn.ts](../../../../../src/conversation-turns/run-turn.ts) L41–151 skips the owned `beforePrompt` user write, managed user presentations, detached user line and ACP input construction when `messages` is absent. It retains recording handlers, transcript bookkeeping and metering, and prepares the named turn for the supervisor. For a backend-only turn, handlers are the session's recording handlers. For a turn that took a submitted message with handlers, the first eligible handlers are wrapped by the same recording code. Completion follows assistant persistence, metering and `afterPrompt`; errors abandon and emit failure. Fake tests check the absence of a user record in all three persistence modes.

`turn_took` merges new message IDs and items into the tracked cause, claims known messages and settles their handles after the named turn's public terminal event. Taken handles resolve with its finalized result or reject with its failure. An earlier public `turn_started` contains the cause known when emitted; a `turn_took` received while the item still waits is visible in its later start event. Unknown/ended turn reports are ignored and logged. Message IDs without a matching submitted handle are logged and cannot settle another handle. Native `turn_took` translation and scripted end-to-end same-turn settlement are both covered.

## Step 6 — Fake and case inventory

[fake-controller.ts](../../../../../test/conversation-controller/fake-controller.ts) implements only the core, with test controls for session scheduling, backend acceptance, independent turns, folding items in, scripted output/results at `prompt()`, cancellation, force stop, held output and options before start. Its usage subscription can register listeners, but no code emits to them, and every scripted prompt returns `usage: null`. Fake usage emission is missing; metering record creation is covered.

[conformance.ts](../../../../../test/conversation-controller/conformance.ts) defines nine shared cases. [conformance.test.ts](../../../../../test/conversation-controller/conformance.test.ts) runs all nine on the session-scheduled fake and on HarnessController with **`lifecycle-agent.ts`** in Agent-owned conversations. The requested **echo** fixture does not run the shared suite. Echo is used to bootstrap some separate fake tests and is characterized elsewhere. The lifecycle fixture gives the shared harness subject explicit tool, silence and failed-load scenarios. [native/conformance.test.ts](../../../../../test/native/conformance.test.ts) runs the same nine against a scripted stdio NativeController in an Agent-owned conversation, adapting assertions for backend scheduling and supervision.

## Changelog and triage

[CHANGELOG-controller-interface.md](../../../../../CHANGELOG-controller-interface.md) covers the required `connection` type change, both renames and deprecated aliases, `harnessConnection()`, and the public types. It includes the neutral capability getter, `UnsupportedError`, `cause`, backend scheduling and message settlement. The headings “for a later native backend” and “none today” for a controller without `reconnect` are historical: NativeController ships and omits it. The local-withdrawal bullet says a later turn naming the ID is ignored; the code and test show the turn still runs and the now-unknown message ID is ignored for settlement. The shared test file header's “interface has no message payload yet” is also stale; `TurnRun.messages` and backend-scheduled content tests exist today.

Two additional offline probes made the coverage gaps concrete:

- A fake turn declared ended and not live replayed with `status: "cancelled"` after calling its cancel method. This differs from the ended-turn cancel contract and was reproduced only on the fake. [Error note](../../../../../.agents/.artifacts/common/errors/11-22-b2-fake-ended-replay-cancel.md)
- The late-output probe used an Agent-owned conversation with the fake. After force stop and rejection it injected a new chunk through the old handlers. The original consumer callback received it and SQLite gained an in-progress assistant snapshot tagged to the **old** turn. The next result stayed clean. This proves the current test can pass even when the stronger drop assertion fails. It does not show that an ACP or NativeController lets such an event reach the session. [Error note](../../../../../.agents/.artifacts/common/errors/11-22-b2-fake-late-output-recorded.md)

Historical implementation commits include `295b0e4`, `733370d`, `c475045`, `977c890`, `42f9b3f`, `5f2dfdc` and `2c1952e`, followed by the owner decisions documented in the original B2 report. The separate `8b4b4f3` cause snapshot change removed only the `kind: "messages"` discriminator. `agent-session.ts` is 4,641 lines. This verification changes no implementation, tests or snapshots.
