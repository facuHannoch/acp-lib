# R4 grounding and proposed implementation brief

Grounded on `integration-r456` at alpha `fe7d28c`. The approved integration baseline is 1,589 tests in 149 files with 35 snapshots. Alpha's changes after `bc974ce` are documentation. This is step 0. Implementation waits for review and release.

## The connection paths now

| Entry | Current code and cancellation gap |
| --- | --- |
| Normal startup | `HarnessController.start` in `src/controller.ts:265` waits for existing teardown, then calls `bringUp` and installs its returned client. `bringUp` creates the ACP client locally, then waits for both initialize and session new/load. `stop` at line 409 sees only the installed client. |
| Fresh startup | `startFresh` at line 279 takes the same path when disconnected. On an existing ACP connection it calls `newSession`, so its pending session RPC needs the same close guard even though a client is already reachable. |
| Reconnect | `reconnect` at line 180 stops the old leaf, uses strict load, then installs the result before validating the requested session. `AgentSession.ensureProvider` at line 3608 reaches this via the neutral reload guard for a recorded ACP ID. It may otherwise start fresh or apply the existing continuation policy. Explicit cancellation must bypass that recovery policy. |
| Mode change | `setMode` at line 437 brings up a replacement while the source is still live, publishes the replacement, then tears down the source. `runSetMode` at `src/agent-session.ts:3296` first ensures the source provider and later updates mode and attachment records. Preserve the source on a genuine target failure and prevent late publication on stop. One connection *attempt* may be active at a time. A live source may coexist with its one candidate. |
| Handoff | `runHandoff` at `src/agent-session.ts:2513` ensures the source, then creates a separate target controller and calls its `startFresh` at line 2624. The target is local to the handoff. The failure path stops it at line 2896, which is unreachable while target startup hangs. Register the target with the conversation before awaiting it and release that registration on every exit. |
| Queue and shutdown | The prompt pump at `src/agent-session.ts:2342` waits for readiness before starting the supervised provider prompt. Settings and mode changes also wait for readiness. The stall supervisor covers dispatched work. Session `stop` publishes stopped, clears queued operations, stops the installed controller and waits for queue idle and record writes. `connection.forceStop` ultimately calls controller stop. Neither can currently reach the local leaf in `bringUp` or the separate handoff target. |
| Agent create/open | The manager starts its owned conversation via `AgentConversation.create` at `src/agent/conversation-manager.ts:831`. The handle enters the live map after that promise resolves. Its openings map deduplicates reopen, and `stopAll` currently waits for openings before stopping the live handles. Agent shutdown must cancel the eager starts it is about to wait for, including initial create and pending adoption load. |

`AcpClient.connect` at `src/client.ts:348` awaits the launcher, starts a local transport, installs it and races initialize against process exit. That race covers process exit, including SIGKILL, and is separate from the ACP SDK's connection abort event. `loadSessionInternal` and `newSessionInternal` await the raw session RPC and install IDs, config and command state without a corresponding close race. `startSession` can fall back from load to new. `bringUp` deliberately keeps an initialized client after some session-creation failures for authentication. Cancellation must bypass both fallback and auth-preserving catches. Raw client `stop` can reach the installed transport, while an unresolved launcher or transport-start step can still finish after stop. The crash callback also needs to verify transport identity before clearing a newer connection.

The existing `AcpTransport.stop` sends SIGTERM, waits a 500 ms grace and escalates to SIGKILL before exactly-once launcher disposal. It already observes the SDK close signal via `onDisconnect`. Reuse both and keep unexpected exit as `ProcessCrashError`. `AcpLauncher.prepare` currently has no signal. Cancellation must prevent a later launcher result from spawning and arrange disposal once if it returns resources. A noncooperative custom launcher can outlive the wait, so it needs either an optional signal for cooperative cleanup or a tracked late-result cleanup. A subprocess inside an external launcher or container remains the launcher's lifecycle responsibility.

`test/fixtures/lifecycle-agent.ts` already suppresses a named RPC with `LIFECYCLE_HANG_CONTROL` before its dispatch switch. It can hang `initialize`, `session/new` or `session/load` without a provider. Its hold control can release a late response. Add a deterministic observation at request receipt using existing wire events or an explicit fixture barrier. The existing test using a hung `session/list` covers running-operation isolation, a different boundary.

## Step 1. Cancellable ACP connection attempt

Extract attempt ownership and transport startup from the three large files before changing behavior. Install a per-controller attempt before any await, share equivalent starts and cancel or join an incompatible attempt before spawning its replacement. Use one epoch/token for startup through synchronous check-and-install. Take shutdown ownership of the candidate as soon as it exists. Cancel before awaiting teardown, ignore callbacks from stale identities and observe all losing promises. If a launcher has not returned, settle the caller immediately and dispose its eventual result without spawning. Reuse the process teardown and add a removable close/abort race around initialize and session creation/load. Normalize an explicit stop or supersession to `ConnectionCancelledError`, preserving genuine failures and auth behavior. Add no connect deadline.

Put `ConnectionCancelledError` in `src/errors.ts`, with public export in `src/index.ts` and readonly code `connection_cancelled`. It belongs next to connection and process errors and applies before operation supervision. Cancellation from native's existing startup deadline keeps its current error contract.

**Gate.** Offline handshake, new and load holds each reject on stop and close the process. Repeated stop shares teardown. A stale reply and a late launcher result cannot install, emit progress, or erase a replacement. Test forced termination of a SIGTERM-resistant fixture, exactly-once teardown, concurrent starts, successful restart after cancellation, unexpected process death and a genuine load failure with its preexisting fallback behavior. Tests wait on named events or fixture barriers and have watchdog bounds. Typecheck and the full clean archive suite pass.

## Step 2. Conversation stop, queue and candidate paths

Own both the currently installed and in-flight candidate controllers during conversation stop. Register and cancel Agent-owned initial creations and opens before draining them on Agent close, including an open that has not exposed a handle. Make connection cancellation bypass continuation recovery and provider-session failure recording. It must leave no late attachment or reconnect fact. Preserve the handoff source on ordinary target failure and preserve the existing handoff error wrapper when a cancelled target follows already-accounted summary or seed work. Its cause is the typed connection cancellation. For a cancelled connection with no completed metered work, surface the typed error directly. Leave the existing cancellation result for ordinary queue clears outside a connect. For a stop during connect, settle the active and waiting queued requests once with the typed connection cancellation and keep undispatched operations unmetered.

**Gate.** Real offline ACP peers exercise direct controller start, fresh start, reconnect, PTY-to-ACP mode replacement and both same- and cross-adapter handoff targets. Test Agent close against eager create and reopen, and stop with a first prompt plus queued prompt/settings while waiting for readiness. Assert the previous recorded binding stays valid, there is no unexpected fresh load, no late `provider_reconnected` or target activation, and no leaked process or unhandled rejection. Test the error cause where a handoff already has metering records. Typecheck and the full clean archive suite pass with the existing A1 snapshots.

## Step 3. Agent-owned ACP provider start policy

Propose `conversationDefaults.providerStart` and `runtime.providerStart` on Agent conversation create and reopen. An explicit runtime value replaces the default. `on_open` is the default and preserves eager startup and error timing. `on_first_use` creates or restores the logical conversation and its capture/continuation state without spawning. The first provider-bound operation shares one readiness attempt. It loads the recorded ID with existing continuation rules or starts fresh for a new conversation. Configuration writes also count as first use. Passive inspection and stopping an unused conversation do not spawn. Empty config/model/command views and neutral capabilities are available before connection. Reading ACP-only capabilities retains its existing not-connected error. A bad provider command or authentication failure surfaces when a provider-bound operation first needs it.

The option is runtime configuration and adds no schema field. A later reopen uses that call's runtime override and the current Agent defaults. Native remains lazy by its existing rules, and managed and standalone sessions and adoption keep their current startup behavior. Recommend limiting the new policy to normal ACP mode, with explicit degraded PTY startup unchanged. Confirm this and the reopen contract before implementation.

The current reopen result is `already_open | loaded | new | recovered` in `src/agent/config.ts:180`. Recommend adding `deferred` for a newly returned lazy ACP handle, so callers can distinguish an unattempted load from a successful one. Preserve each eager result. Do not synthesize provider acquisition records on lazy open. Keep the recorded provider ID and metering context as the first-use recovery authority, including for a missing prior session.

**Gate.** Test default eager create/open, explicit lazy creation and reopen, passive lookups, one spawn on first prompt or settings change, concurrent first use, strict loading of the recorded ID, missing-session continuation, launch/auth error timing, stop before use, and stop during first use. Test runtime override precedence and compatibility with native, managed and adopted conversations. Typecheck and the full clean archive suite pass.

The manager starts at 1,013 lines and the plan's no-growth rule applies there too. Keep extraction and each concern small.

Review the proposed typed handoff cancellation rule, the optional launcher cancellation signal, the lazy reopen status and PTY scope. Awaited direct or managed factories do not expose a session handle before they return. If those callers must cancel an eager open themselves, approve an optional caller signal for that boundary. Controller-level stop and Agent close can own their attempts without widening the standalone factory API. The main risks are a child launched after stop, late results publishing an obsolete attachment or mode, failure recovery issuing a new request after explicit cancellation, and shutdown waiting for a queue or handoff candidate it cannot reach.
