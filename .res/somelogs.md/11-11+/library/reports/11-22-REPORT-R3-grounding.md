## Decision and deadline

1. Keep R2 final levels. A valid `permissionRule` result takes precedence, then ACP uses its most restrictive matching rule, then the configured default. Native skips ACP rules. Final allow or deny resolves immediately as `by: "default"`, which covers the automatic policy path. A native host responder is the existing explicit exception, with its own authority and `by: "handler"`.
2. For an ask, try the selected prompt handler first. Its answer is `by: "handler"`. Otherwise, if `answersPermissions` is true, wait for the consumer to claim an offered option until the deadline. A successful claim is `by: "consumer"`. The timer uses the deny selection and `by: "timeout"`. Preserve the recorded denied outcome for an automatic refusal where ACP only offers cancellation.
3. With an ask and no declared answerer, apply the setting's default immediately. This matters when an ask rule or callback overrode an allow or deny default. If the default itself is ask, refuse immediately and classify it as `by: "default"`. There is no second policy pass. This replaces R2's refusal of every unattended ask.

Add `answersPermissions` (default false) and `permissionTimeoutMs` (default 300,000 ms) to the conversation config used by `conversationDefaults` and expose them on `CreateAgentConversationConfig`. Forward the same optional fields on reopen so consumers can reestablish runtime responsibility, inheriting defaults through the manager and honoring explicit false. This is runtime configuration and requires no new columns or permission record fields. Validate positive finite bounds before opening an operation, with a configured wait strictly below the harness's built-in ten-minute default. If the harness uses a shorter timeout, its close can win.

Stamp ACP where the RPC arrives, before projection or persistence. To measure from the actual native request even when observed for the first time after a hold or reconnect, add an additive `requestedAt` field to the native request at gate creation, including in `channel/observe`. The timestamp also supports the public epoch-ms `expiresAt`. For an older harness without the field, use first host receipt, kept across replays, and document that limit. Derive the remaining budget once from the timestamp, then measure elapsed local time with a monotonic clock. A held request still reaches the conversation with its turn. If it is already past deadline when drained, the event pair closes immediately without starting a fresh five-minute wait. Enforce expiry at answer claim as well as from the timer. Recommend using the same deadline to bound otherwise nonsettling handler callbacks, including the configured native responder, while preserving their precedence. ACP ingress is the earliest ACP timestamp available.
