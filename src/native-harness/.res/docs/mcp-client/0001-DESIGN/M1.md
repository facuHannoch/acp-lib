# M1 contract and offline probe

Base alpha `25d9eb9e3e2648e300070fc2453e9362484eb8b5`.
This gate contains only the decision, contract details and an offline probe.

## Wire and trust

- `ProtocolConfig.mcpServers?: Record<string, McpServer>`. Each entry has
  `enabled?: boolean` (default true). Stdio is
  `{ transport: "stdio", command: string, args: string[], cwd?: string,
  env?: Record<string, { env: string }> }`. HTTPS is
  `{ transport: "http", endpoint: string,
  headers?: Record<string, { literal: string } | { env: string } | { runtime: true }> }`.
  Strictly reject unknown fields, invalid names, NUL in spawn arguments,
  duplicate case-folded headers and control characters in headers. Resolve
  variable references at executable open, rejecting absent or empty values
  from that entry without logging values. Spawn directly via runner, no shell,
  no ambient environment, and reap owned children. Bound stderr at 8 KiB
  of transient buffering and expose only sanitized error categories.
- HTTPS requires certificate validation and an absolute canonical HTTPS
  endpoint without userinfo, query or fragment. No redirects, proxies,
  cookies, OAuth negotiation, legacy HTTP+SSE or ambient auth. Forbid
  Host, Cookie, Set-Cookie, Content-Length, Accept, Content-Type,
  MCP-Session-Id, MCP-Protocol-Version, Last-Event-ID, Origin, Upgrade,
  Expect, TE, Trailer, Transfer-Encoding, Connection, and names prefixed
  Proxy-, Sec- or MCP-. Authorization requires a reference or runtime secret,
  never a portable literal. Other literal values are explicitly nonsecret.
  The optional owner-only executable create/open field
  `mcpRuntimeHeaders?: Record<string, Record<string, string>>` supplies
  resolved values for declared runtime headers on configured HTTPS entries.
  A declaration must be exactly one of the three variants, with no extra
  keys. The runtime variant requires literal boolean true. Validate header
  names case-insensitively in both maps, reject case-folded duplicates,
  undeclared names, reserved names, malformed material, and material
  targeting an env/literal header or a stdio entry. Reject a malformed or
  unauthorized executable request before using any supplied values. Only
  the trusted owning launcher may supply this field. Participant and model
  inputs cannot supply it.
  The runtime declaration survives portable save/export/import without its
  value. Validation, inspection and import require no material and reject any
  attempt to supply it. On executable
  create and every executable reopen, including reconnect, if a declared
  runtime header is missing or empty for an enabled entry, report that entry as
  unavailable with reason config and issue no request for it. Other entries
  and session work continue. A disabled entry needs no material. Never
  include values in saved config, archives, checkpoints, status, captures
  or diagnostics.
  Bind every actual fetch, including stream and cancellation requests, to the
  configured endpoint and require HTTPS; prevent SDK automatic resumption or
  retries of tool POSTs and disable unsolicited persistent GET streams in v1.
- Proposed initialize addition `capabilities.mcpServers?: {stdio:boolean,
  http:boolean,sse:false}`, absent equivalent to unsupported. acp-client
  forwards these to its existing native capability slot. Executable open
  and status expose `mcpServers?: Record<string, { transport: "stdio" | "http",
  state: "ready" | "disabled" | "unavailable",
  reason?: "config" | "spawn" | "connect" | "discovery" | "limit" | "closed" }>`.
  Inspection/import do not connect or resolve environment variables.
- A named policy has `mcp?: "allow" | "deny"`; absent denies, also for
  `__legacy_allow`. An empty contributing set denies. The host owns policy
  selection in the admitted channel configuration and `channel/push.item.policy`;
  participant input never supplies that wire field. Channel defaults and
  inherited notices contribute according to the existing policy snapshot.
  Test the trusted launcher attribution boundary, including a guest using
  the owner's name and including policy-like text. To preserve legacy
  fingerprints append a versioned compatibility component only if MCP is
  configured or a policy explicitly sets the grant. Bind sorted grants,
  portable server settings and the effective public catalog identity (names
  and canonical definition/schema); exclude resolved secrets and live
  connection generation.

## Discovery and dispatch

One connection per enabled entry per executable session; channels share it.
Maximum 8 entries, common 10-second startup budget per entry (spawn/connect,
negotiation and discovery), at most 4 concurrently starting. Maximum 4 discovery
pages, 32 tools per server and 64 per session, 8 KiB canonical input schema
per tool and 128 KiB total registration bytes. Reserve the session quota in
configured name order, independent of network completion order. Exceeding
any limit or duplicate remote names rejects that server's whole catalog.
Failed servers do not prevent other tools or session work. Catalog refresh
only on executable reopen or explicit server reconnect in v1; ignore
list-changed notifications. Reconnect never replays commands.

Server names are lowercase ASCII matching `[a-z][a-z0-9]{0,11}`. Remote
names are nonempty UTF-8 (reject unpaired surrogates), maximum 22 bytes; route
as `mcp__<server>__<lowercase UTF-8 hex>` (maximum 63 characters). Keep an
explicit binding, never derive authority from the model name. Reserve the
entire prefix even when no server is enabled. Reject unsupported schema
definitions at registration. Accept only object-root JSON Schema with
nested types object, array, string, boolean, integer, number and null;
allow properties, required, additionalProperties (boolean), items (single
schema), scalar enum, description and title. Reject unknown or misplaced
keywords, repetitions in required/enum, undeclared required names, and
unsupported references, unions, coercion, defaults and annotations that
affect validation. Max depth 8 and 128 nodes. Bound call args to 16 KiB
serialized UTF-8. Validate against the exact offered schema before policy
and recheck the binding and permission immediately before marking dispatch.
No offer forgery or remapping after replacement, even for equal names.

## Calls and receive limits

`limits.mcpCallTimeoutMs` is 30 minutes by default, range 1 second to 30 minutes.
Own a monotonic absolute deadline from durable dispatch through result parsing.
The SDK defaults to 60 seconds, so override each call explicitly and disable
progress reset. Require the launcher/host not to impose a shorter timeout.
A fixture uses scaled intervals; v1 expects progress about every 25 seconds
and ordinary approval to finish within about 23 minutes. Accept progress only
for the matching outstanding token and drop it at settlement. Do not retain
remote progress text. Send one `notifications/cancelled` with the original ID
on abort/timeout while writable, with a separate cleanup budget of 250 ms.
Ignore late replies, bound the local wait and leave unrelated invocations
usable. Use no automatic replay after dispatch, including SDK reconnect paths.

Cap inbound newline frames and decoded response/SSE bodies at 256 KiB before
SDK JSON parsing. Use byte accounting, limits on partial frames and a fatal
UTF-8 decoder for stdio, and a counting response-body wrapper for every SDK
fetch; do not rely on Content-Length. Bind the HTTP fetch URL and forbid
redirects before sending credentials. Reject batching and unsupported methods.
A protocol error or malformed/oversized inbound frame invalidates the
connection when its request cannot be isolated. Shutdown aborts calls,
closes the transport and reaps owned subprocesses. Preserve original server
and tool identities in sanitized operator diagnostics.

Use existing paired outcomes with codes `tool_unavailable`,
`invalid_arguments`, `policy_denied`, `tool_interrupted`, `tool_timeout`,
`mcp_tool_error`, `mcp_protocol_error`, `mcp_result_too_large` and
`mcp_uncertain`. A disconnect after possible send is uncertain even if
no reply arrives. Keep failure messages local and bounded; do not echo
credentials, raw server exceptions or server instructions. Treat result
text as external data. Success preview is complete JSON with
`{text, structuredContent, omittedContentBlocks, truncated}`. Preserve
supported text, whole structured JSON or null, and the count of unsupported
image/audio/resource blocks. Fit 2048 serialized UTF-8 bytes by first omitting
oversized structured data, then clipping text at scalar boundaries; set
`truncated` for either operation. No unsupported block payloads enter the
model. Keep the active assistant call and all paired results intact for the
next inference, or return `context_limit` before model contact. Compose the
same active exchange treatment with G2 and reuse durable trace/paired results.

## Launcher and verification

At M4 the trusted upstream native launcher maps `harness.config.mcpServers`
to managed `ProtocolConfig.mcpServers` on create and executable reopen,
and supplies any separately resolved material through `mcpRuntimeHeaders`.
Existing non-native launchers retain their paths. W18 proves a real native
session receives both entries, discovers and calls each, denies guest access,
and reapplies credentials on reopen. Test portable export/import with a
runtime header declaration and a secret canary: the declaration survives,
the canary is absent, and executable create/reopen without material leaves
the entry unavailable with zero HTTP requests. The launcher gate supplies
the material on create and reopen and verifies delivery only to the configured
endpoint, with no value carried over from the first connection. Upstream launcher and W18 are outside
this repository and require an integration handoff. No service-owner
confirmation or sanitized transcript was available at submission. Real
agents-tools and door approval are compatibility dependencies. If either
requires elicitation or task augmentation, that flow needs a separate gate.

The [probe](../../../../test/probes/mcp-sdk.mts) runs in an isolated package.
It does not change runtime dependencies. On Bun 1.3.14 run this with the
SDK already present in the npm cache:

```sh
probe_dir=$(mktemp -d)
cp test/probes/mcp-sdk.mts "$probe_dir/"
cd "$probe_dir"
npm install --offline --ignore-scripts --no-audit --no-fund @modelcontextprotocol/sdk@1.31.0 zod@4.6.5
for revision in 2025-03-26 2025-06-18 2025-11-25; do
  bun mcp-sdk.mts "$revision" || exit
done
```

All six transport/revision cases passed. The same fixture logic covers
negotiation, discovery, progress, server receipt of abort and timeout
notifications with original request IDs, and subsequent calls on the same
connection. The HTTPS probe uses a generated loopback certificate, explicit
fixture header, exact endpoint check, redirect refusal configuration and
a pre-parse streaming byte counter. The probe is not production transport
conformance: oversize and redirect negative cases, hard cleanup, actual
23-minute timing, model inference, policy spoofing and launcher gates remain
for M2–M4. No live external calls. Shared config, session assembly, tool
registration and context edits must be coordinated with G2 before runtime.

### Exact credential echoes

Keep resolved nonempty environment references and runtime header material
only for the executable connection. Before projection, redact literal
occurrences in remote text and nested structured strings. A key containing
such material makes the result unsafe to project. Refuse that result with a
fixed local error. Reject a catalog if a credential occurs in a tool name or
schema, since changing either could change dispatch. Descriptions may be
redacted. Remote error text and progress data remain excluded. The same
rule applies to stdio environment references and HTTPS env/runtime headers.
This covers exact echoes and does not detect arbitrary transformations of a
credential. Test the paired result, next model request, inspection, portable
export and offered definitions with a synthetic canary.

### Streamable HTTPS transport

The runtime uses the SDK Streamable HTTP transport over a private Undici
dispatcher (7.29.0). Bun's default fetch and Node HTTP shim inherit ambient
proxy settings even with an empty proxy option. The private dispatcher has
neither a proxy nor global credentials. It validates TLS, uses the exact
configured path, sends no redirects or unsolicited GETs, and requests
identity coding. Unexpected content encoding is refused before parsing.
The session has one logical transport per server, with separate HTTP
requests for concurrent calls and cancellation. Transport abort and bounded
cancellation keep the original call from retaining a stream. A disconnect
before a streamed reply closes that transport, yields uncertainty, and
does not replay the call. An executable reopen rediscovers the catalog and
requires fresh runtime header material. Launcher support remains M4.
